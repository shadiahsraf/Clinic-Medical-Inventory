# نظام إدارة مخزن المستلزمات الطبية — الدليل الشامل والتوثيق الفني

تطبيق مكتبي متكامل باللغة العربية مبني باستخدام Python و PySide6 وقاعدة بيانات SQLite لإدارة المخزون الطبي للعيادات والمراكز الصحية بنظام التكلفة الوارد أولاً يُصرف أولاً (FIFO).

> 📖 **للاطلاع على التوثيق التفصيلي والموسوعة الفنية والتشغيلية الكاملة لكل جداول وشاشات وعمليات النظام، راجع ملف:**  
> **[الموسوعة الفنية والتشغيلية الشاملة (DOCUMENTATION_AR.md)](file:///d:/DjangoProjects/clinic/DOCUMENTATION_AR.md)**

## 1. الغرض من التطبيق (Application Purpose)
يهدف النظام إلى أتمتة دورة التموين والمستلزمات الطبية في العيادات والمراكز الطبية بشكل دقيق وآمن:
- إدارة الأصناف الطبية بباركود وأكواد فريدة دائمة غير قابلة للتغيير.
- متابعة الوارد من مشتريات وتبرعات عينية ونقدية.
- صرف المستلزمات للأقسام والعيادات وحساب تكلفة الاستهلاك الفعلي بنظام FIFO.
- معالجة المرتجعات واستعادة تكلفة الدفعة الأصلية.
- حصر الهالك والتالف وتوثيق أسبابه وأثره المالي.
- إجراء دورات الجرد ومقارنة الأرصدة الدفترية والفعلية ومعالجة الفروق بقيود تسوية نظامية.
- إدارة الموردين ومتابعة فواتيرهم وسداد مدفوعاتهم وأرصدتهم المتبقية.
- لوحة تحكم ذكية وإشعارات سطح مكتب للرصيد المنخفض ونفاد المخزون.
- حماية العمليات بنظام أدوار وصلاحيات وسجل مراجعة وتدقيق غير قابل للحذف (Audit Log).
- حفظ واستعادة نسخ احتياطية متسقة وقابلة للفحص.

## 2. متطلبات النظام (System Requirements)
- **نظام التشغيل**: Windows 10 أو Windows 11 (64-bit) أو ما يعادله.
- **البيئة البرمجية**: Python 3.10 فأحدث (أو الحزمة المجمعة القابلة للتشغيل .exe مباشرة بدون بايثون).
- **المكتبات الرئيسية**: PySide6, SQLAlchemy, ReportLab, arabic-reshaper, python-bidi, openpyxl, argon2-cffi.
- **الشاشة**: دقة عرض 1280×720 بكسل على الأقل.
- **طابعات وماسحات الباركود**: يدعم جميع ماسحات الباركود USB (Barcode Scanners) وطابعات A4 والطابعات الحرارية لملصقات الباركود.

## 3. التثبيت والتشغيل (Installation)
1. **تثبيت المتطلبات عبر pip**:
   ```bash
   pip install -r requirements.txt
   ```
2. **بدء تشغيل التطبيق**:
   ```bash
   python run_app.py
   ```
3. **أو عبر بناء الحزمة التنفيذية Windows**:
   تشغيل السكربت `build_windows.bat` للحصول على الملف التنفيذي `dist/ClinicInventory.exe`.

## 4. موقع تخزين قاعدة البيانات (Database Storage Location)
- تُحفظ قاعدة البيانات محليًا داخل مجلد المستخدم الدائم:
  ```
  %APPDATA%\ClinicInventory\inventory.db
  ```
- هذا المجلد آمن ودائم ولا يُحذف مطلقًا عند ترقية أو إعادة تثبيت البرنامج.
- تعمل قاعدة البيانات بنظام SQLite مع ميزات `WAL` و `PRAGMA foreign_keys=ON` لحماية سلامة البيانات والربط العلائقي.

## 5. التشغيل لأول مرة وإعداد مدير النظام (First Launch & Admin Setup)
- عند تشغيل البرنامج لأول مرة وقاعدة البيانات فارغة، تظهر تلقائيًا نافذة **«إعداد أول مستخدم»**.
- يُطلب إدخال:
  - الاسم الكامل
  - اسم المستخدم
  - كلمة المرور (6 أحرف على الأقل)
- يتم إنشاء المستخدم برتبة **«مدير النظام»** وحفظ كلمة المرور مشفرة بأقوى خوارزميات التشفير (Argon2id).
- لن تظهر هذه النافذة مرة أخرى، وسيتم التحول إلى نافذة تسجيل الدخول الدائمة.

## 6. أدوار وصلاحيات المستخدمين (User Roles & Permissions)
يحتوي النظام على نظام صلاحيات مشدد:
1. **مدير النظام (Admin)**: كامل الصلاحيات لإدارة المستخدمين، الصلاحيات، النسخ الاحتياطي، الإعدادات، اعتماد الجرد، وتعديل الأدوار.
2. **أمين المخزن (Storekeeper)**: إدارة الأصناف، الموردين، الأقسام، تسجيل الوارد، صرف المستلزمات، تسجيل المدفوعات، استبعاد الهالك، إجراء الجرد، واعتماد المرتجعات.
3. **مسؤول الصرف (Issuer)**: صلاحيات مقيدة لصرف المستلزمات للعيادات، تسجيل المرتجعات، وعرض رصيد المخزون والتنبيهات.

> **قواعد الأمان**:
> - لا يمكن لأي مستخدم عادي ترقية نفسه أو غيره إلى رتبة «مدير النظام».
> - لا يمكن للمستخدم تعطيل حسابه الحالي.
> - تُسجل جميع التعديلات في سجل المراجعة (Audit Log).
> - لا تُخزن ولا تُعرض كلمات المرور كنص صريح أبدًا.

## 7. دليل استخدام الوحدات الرئيسية

### أ. إدارة الأصناف (Item Management)
- لكل صنف **كود فريد دائم** (مثل `IT-00001`) لا يتكرر ولا يمكن تعديله بعد إنشائه لحماية الأثر التاريخي.
- يمكن تحديد الوحدة الأساسية، التصنيف، الحد الأدنى، ورقم الباركود (EAN/Code128).
- يدعم البحث الفوري بالاسم أو الكود أو قراءة الباركود عبر الماسح.

### ب. الوارد إلى المخزن (Incoming Supplies)
- **المشتريات**: تتطلب تحديد المورد، رقم الفاتورة، الكميات، أسعار الشراء، وتاريخ الصلاحية. يمكن سداد دفعة فورية أو تسجيلها آجلًا.
- **التبرعات العينية**: تسجيل اسم المتبرع والقيمة التقديرية (لتقييم المخزون دون التأثير على حركة النقدية).
- عند تأكيد الوارد، يتم إنشاء دفعات (`Batches`) جديدة تسجل في دفتر حركة المخزون غير القابل للتعديل (`Stock Movements`).

### ج. صرف المستلزمات واحتساب التكلفة FIFO
- عند إنشاء سند الصرف لقسم أو عيادة:
  - يخصص النظام الكميات تلقائيًا من أقدم الدفعات الصالحة المتاحة (الوارد أولاً يصرف أولاً).
  - لا يمكن الصرف بالسالب، ويتم رفض العملية بالكامل في حال عدم كفاية الرصيد.
  - سندات الصرف محمية بمفتاح منع التكرار (`idempotency_key`).
  - يمكن طباعة وتصدير **سند صرف رسمي** يتضمن الأصناف، التكلفة، ومساحات التوقيع.

### د. المرتجعات (Returns)
- يتم اختيار سند الصرف الأصلي ثم اختيار الصنف.
- يمنع النظام إرجاع كمية أكبر من المصروفة فعليًا.
- **مرتجع صالح للاستخدام**: يعود للمخزون ويسترد تكلفة الدفعة الأصلية تلقائيًا.
- **مرتجع تالف**: يُقيد كتالف ولا يعود لرصيد المخزون الصالح.

### هـ. الهالك والتالف (Damaged Supplies)
- اختيار الصنف والدفعة المحددة.
- إدخال الكمية وسبب الاستبعاد (كسر، انتهاء صلاحية، عجز، أخرى).
- يقوم النظام باحتساب التكلفة المخزنية للكمية المستبعدة وتخفيض رصيد الدفعة بدقة.

### و. الجرد والتسويات (Stocktaking)
- فتح جلسة جرد تثبت الأرصدة الدفترية لجميع الأصناف.
- إدخال الكميات الفعلية المعدودة وحساب الفروق تلقائيًا.
- في حالة وجود أي عجز أو زيادة، **يلزم النظام المستخدم بتقديم تفسير ومبرر كتابي**.
- عند اعتماد الجرد من قبل المسؤول المصرح له:
  - يُعالج العجز باستهلاك FIFO نظامي.
  - تُعالج الزيادة بدفعة تسوية جديدة بتكلفة أحدث دفعة مسجلة.
  - لا يتم أبدًا الكتابة المباشرة فوق أرصدة الجداول لضمان النزاهة المحاسبية.

### ز. حركة المخزون وسندات الصرف المطبوعة (Movement Ledger & Vouchers)
- سجل حركة تفصيلي يعرض كل حركة (وارد، صرف، مرتجع، هالك، تسوية) مع التاريخ، الصنف، الدفعة، القيمة، المستند، والمسؤول.
- تصدير سندات الصرف إلى PDF بتشكيل وتنسيق عربي أصيل من اليمين لليسار.

### ح. الباركود وطباعة الملصقات (Barcode Support)
- استخدام ترميز Code128 المتوافق قياسيًا مع ماسحات الباركود USB.
- طباعة ملصق فردي للطابعات الحرارية أو صفحة كاملة A4 تحتوي على 24 ملصقًا تتضمن اسم الصنف بالعربية، الكود، والباركود.

### ط. التنبيهات وإشعارات سطح المكتب (Alerts)
- فحص دوري للأصناف التي وصل رصيدها للحد الأدنى أو نفد بالكامل.
- ظهور إشعار عربي على شريط مهام ويندوز (Windows Toast / Tray Notification).
- شارة رقمية بجوار بند «التنبيهات» في القائمة الجانبية.
- عدم تكرار إرسال التنبيهات للحالة الواحدة غير المعالجة.

### ي. النسخ الاحتياطي والاستعادة (Backup & Restore)
- إنشاء نسخ احتياطية يدوية وتلقائية متسقة باستخدام محرك SQLite Online Backup API.
- فحص سلامة النسخة والتحقق من بنيتها قبل الاستعادة.
- **نسخة أمان تلقائية (Safety Backup)**: يقوم النظام بأخذ نسخة احتياطية إجبارية من البيانات الحالية قبل تنفيذ أي عملية استعادة لمنع فقدان البيانات.

## 8. آلية ترقيات قاعدة البيانات (Database Migrations)
- يعتمد النظام آلية ترقيات ذاتية مدمجة (`clinic_inventory/bootstrap.py`) تناسب العمل المكتبي دون الحاجة لأدوات خارجية معقدة:
  - يُسجل رقم إصدار المخطط في جدول الإعدادات: `schema_version`.
  - عند تشغيل إصدار جديد برقم `SCHEMA_VERSION` أعلى، يتم:
    1. أخذ نسخة أمان احتياطية كاملة من ملف قاعدة البيانات بصيغة `.bak` قبل أي تعديل.
    2. تنفيذ خطوات الترقية المحددة في مصفوفة `MIGRATIONS` بالتتابع داخل معاملة (`Transaction`).
    3. تطبيق الفهارس أو التعديلات دون حذف أي جداول أو تفريغ بيانات المخزون السابقة.
    4. تحديث رقم الإصدار إلى الإصدار الجديد.

## 9. استكشاف الأخطاء الشائعة (Troubleshooting)
- **مشكلة ظهور مربعات بدل الحروف العربية في ملفات PDF**:
  تأكد من وجود خط `DejaVuSans.ttf` داخل المجلد `clinic_inventory/assets/pdf_fonts/`، أو توفر خطوط النظام العربية القياسية مثل Tahoma / Arial في ويندوز.
- **البرنامج لا يفتح أو تظهر رسالة قفل قاعدة البيانات**:
  تأكد من عدم فتح ملف `inventory.db` في برنامج تصفح خارجي مثل DB Browser for SQLite بوضع القفل الحصري. النظام يستخدم وضع `WAL` لتجنب تعارض القراءة والكتابة.
- **تنبيهات ويندوز لا تظهر**:
  تأكد من تفعيل إشعارات التطبيقات في إعدادات نظام Windows (الإشعارات والتركيز)، وستظل شارة التنبيهات داخل البرنامج تعمل باستمرار.
